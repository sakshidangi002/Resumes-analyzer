# ============================================================================
# Softwiz HRMS + Resume Analyzer - ALL Python dependencies, one file.
#
#     python -m venv .venv
#     .venv\Scripts\pip install -r requirements.txt      (Windows)
#     .venv/bin/pip install -r requirements.txt           (Linux)
#
# WHY ONE FILE
# ------------
# The two applications run as ONE process in ONE virtualenv - run_app.py
# starts `uvicorn app.main:app` and the Resume Analyzer is mounted inside the
# HRMS backend. Splitting the dependencies across four files never matched
# that, and it went wrong in two ways that cost a developer a day:
#
#   * 13 packages were declared in two files with DIFFERENT pins (fastapi
#     ==0.110.0 vs >=0.109.0, and so on). Both installed into the same venv,
#     so whichever was installed last silently won.
#   * 8 imported packages were declared in none of them, so setup failed one
#     ModuleNotFoundError at a time - and the error names a module, not a
#     package, so each one had to be guessed.
#
# Versions below are >= whatever is actually running on the machine this
# system works on, not aspirational pins. The old file claimed torch==2.1.2
# while 2.12.1 was doing the work.
#
# Checked by scripts/audit_requirements.py and tests/test_requirements_complete.py
# - CI fails if an import is added without being declared here.
# ============================================================================
